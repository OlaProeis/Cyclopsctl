# PRD bootstrap CLI

`cyclopsctl bootstrap` takes a project from PRD to native tasks, optional complexity analysis, and a synced first `current-handover-prompt.md` — without cyclopsctl-owned task generation during cycles or agent involvement.

## Command

```bash
cyclopsctl bootstrap --project-root /path/to/project
cyclopsctl bootstrap --from-prd prd.md --skip-analyze --tag feature-x
cyclopsctl bootstrap --sync-handover-only
cyclopsctl bootstrap --append --with-workflow
```

Shared flags: `--no-env`, `--config`, `--project-root`, `--current-handover`, `--complexity-report`, `--tag`, `--plain`.

Bootstrap-only flags:

| Flag | Effect |
|------|--------|
| `--from-prd PATH` | PRD file (default: `prd.md` in project root) |
| `--skip-analyze` | Skip complexity analysis after parse |
| `--sync-handover-only` | Regenerate handover only; skip init/parse/analyze |
| `--append` | Append tasks when re-parsing PRD |
| `--with-workflow` | Generate project-aware workflow files from PRD and repo metadata |
| `--force-workflow` | Overwrite workflow files even when customized |
| `--force PATH` | Force overwrite specific workflow file (repeatable) |
| `--tech-stack TEXT` | Override tech stack in generated workflow files |
| `--test-cmd CMD` | Override test command in generated workflow files |
| `--ai-context PATH` | ai-context path for handover environment defaults |

## Pipeline

When not using `--sync-handover-only`:

1. **Ensure native storage** — scaffold `.cyclopsctl/tasks/` when missing via `NativeTaskBackend.init_project()`.
2. **Parse PRD** — `parse_prd_with_cursor` via Cursor SDK (`CURSOR_API_KEY` required).
3. **Analyze complexity** — `analyze_complexity_with_cursor` unless `--skip-analyze`.
4. **Sync handover** — `cyclopsctl tasks next` + `show`; write `current-handover-prompt.md` with `# Task ID:` and standard section order (see `prompts/sync-current-handover.md`).
5. **Workflow generation** (optional) — generate project-aware `ai-context.md`, `update-handover-prompt.md`, and `docs/index.md` when absent or generic and `--with-workflow` is set (see `docs/workflow/workflow-generation.md`).

Bootstrap does **not** mark tasks done, run agents, or rewrite `update-handover-prompt.md`.

On success, stderr prints next steps: `cyclopsctl doctor`, then `cyclopsctl run --cycles N`.

## Handover sync

Handover content is generated by `render_synced_handover()` in `prompt.py` from native `tasks show` output and optional complexity report scores. Empty queue writes `# Task ID: 0` with a completion notice.

## Errors

| Condition | Result |
|-----------|--------|
| Missing PRD (when parse required) | `BootstrapError`: PRD file not found |
| Parse / analyze / init failure | `BootstrapError` with underlying SDK or store error |
| Missing bundled templates with `--with-workflow` | `BootstrapError` |

## Implementation

| Symbol | Module | Role |
|--------|--------|------|
| `run_bootstrap` | `bootstrap.py` | Pipeline orchestration |
| `resolve_bootstrap_backend` | `bootstrap.py` | Path resolution and flag bundle |
| `render_synced_handover` | `prompt.py` | Handover Markdown from `TaskShowDetail` |
| `parse_prd_with_cursor` | `tasks/parse_prd.py` | PRD → tasks via Cursor SDK |
| `analyze_complexity_with_cursor` | `tasks/analyze.py` | Complexity report via Cursor SDK |
| `_bootstrap_command` | `cli.py` | Subcommand wiring |

Bundled templates: `src/cyclopsctl/templates/` (included in wheel via hatch `force-include`).

Tests: `tests/test_bootstrap.py`.
